# 31 · 用户偏好与沟通方式

> 这些不是视频规则，是**和这位用户合作的方式**。新 AI 不知道这些，最容易惹用户不满。

## 一、语言和格式
- **【必须】所有给用户看的文字一律用中文**，包括提示框、提问、按钮（10-18 英文提示框，用户“啥意思，我没看懂”）
- 大白话；抛选择题时先说清每个选项是什么、后果是什么，再给推荐（推荐放第一个）
- 选项内容**写在消息正文里**（提问工具的预览栏用户看不到）
- 给用户复制的东西放代码框

## 二、思考方式（用户全局要求）
“首要规则：逆向思维 + 共情”：先想他为什么这么问、真正要解决什么；字面问题和真实需求不一致时**先点出落差，再回答**；追问要短而准。
例：用户问“是不是很多动画都简化了”——真实需求是“把画面做回正片水平”，直接承认并改。

## 三、什么时候必须先问、什么时候直接做

| 必须先问用户，回复前不往下做 | 直接做，做完汇报 |
|---|---|
| 每集的开头（3–4 个候选） | 知识卡 |
| **剧本写完给用户过目**（第二篇每集） | 配音、画面、抽帧、修版式、出片 |
| 长片 / 汇总 / 终章的文稿 | 发布文案、规划表 |
| 片长要不要变（10-30 用户定回到 4–5 分钟、不再压缩） | 按已定规范修正明显错误 |
| **仓库里没有的新角色**（说要什么样，等用户出图） | 把用户指出的错误写进规范 |
| 画风、角色样子、配色、版式、封面版式、配音音色 | 外部复核里“原著说错了”的地方 |
| 外部复核 / 诊断里和用户已定规则冲突的部分 | |
| 已发布的集要不要重做（默认不重做） | |
| “代入型”开头（带评论区钩） | |

**不要每一步都来问**；左栏的事用户回复前不能往下做。

## 四、用户亲自定的东西不能被覆盖（10-29 教训）
- 用户定的开头、封面问题、标题、角色，后面任何外部诊断都**不能擅自换掉**；要动先单独问，或只改诊断点到的那一句
- 10-29 EP22：用户定的开头是外贸场景“做买卖，跑外贸才赚大钱？”，外部诊断说口径混了，AI 把第一句换成“商人赚得多，就更养本国人？”。用户指着 `_历史版本` 说：“22 集不是开头用外贸那个场景吗，没有同步好记忆”。
- 做法：用户在某个对话里定下的东西，**当场写进 `审核记录.md` 改稿记录或 AI 记忆**；改别的对话做过的集前，先翻审核记录、`_历史版本`、规划表

## 五、交付时怎么说
- 先说结果：做好了什么、时长、在哪（带集号的文件名）
- **如实说没做的、没验证的**（“片子还没上传”“这个数是估算”“横屏封面还没看”）
- 自己估错了主动说（EP15s 文稿写“约 9 分钟”，实际 5 分 10 秒）
- 改开头重出的提醒拿 `_历史版本` 旧版做 A/B
- 最后给一个明确的下一步问题，带 1–2 个按钮

## 六、用户在意什么
1. **内容准确**：数字、引文、说法和原著一致；不夸大、不替斯密说话；表述通顺
2. **开头抓人**：观众心里那句话、短、快进故事
3. **有人味**：角色有反应、顶嘴、表情；像聊天不像上课
4. **画面精致、和谐、不割裂**：第二篇和第一篇融合；只放相关角色；不单调；色调对（第一篇纸色）；肤色有血色
5. **专业又通俗**：点名一个概念、讲清机制和适用条件
6. **声音舒服**：配音亲和从容不着急；音量稳定
7. **文件整洁**：一集一个文件夹、文件名带集号、旧版进 `_历史版本`

## 七、安全和边界【必须】
- 火山引擎密钥在 `studio\.env`：永远不读出、不写进文档、不发到网上
- **不登录用户的抖音账号**，不替用户发布、评论、私信
- 下载任何新东西（软件、素材、字体）前先问
- 不改别的对话正在改的文件、不改心理号（`心理号\`、`studio\src\xl*\`）；用户的角色素材原包 `D:\AI\codex\视频项目\…\v16_video_cast` 只读
- 不给投资建议；不评价今天的政策

- 国富论号「看得见的手」：本手册
- 心理号（像素风，规范 `D:\AI\短视频\心理号\心理号制作规范.md`）：和本手册无关，规则不混用
